---
name: pre-check-test
description: commit/push/PR 전 CI 검사를 로컬에서 미리 실행하고, 에러 발생 시 개발자 승인 후 자동 수정합니다
---

commit → push → PR 시 실제로 실패할 수 있는 항목을 로컬에서 미리 확인합니다.
에러가 있으면 어느 항목이 실패했는지 보여주고, 개발자 승인 후 자동 수정을 진행합니다.

## 절차

### 1. 현재 브랜치 및 상태 확인

```bash
git branch --show-current
git status --short
```

결과를 출력하여 개발자가 현재 상태를 파악할 수 있게 한다.

### 2. CI 검사 실행

`test-runner` 서브에이전트를 호출하여 아래 두 명령어를 순서대로 실행한다.  
첫 번째가 실패해도 두 번째를 반드시 실행하여 **모든 에러를 한 번에 파악**한다.

```bash
# format:check + type-check + lint + test + build 전체
pnpm ci:check

# 보안 감사 (GitHub Actions PR 단계에서 별도 실행됨)
pnpm audit --audit-level=high
```

### 3. 결과 리포트 출력

```
# /pre-check-test 결과

## CI 검사 (pnpm ci:check)
- 포맷 검사 (format:check): ✅ 통과 / ❌ 실패
- TypeScript 타입 체크: ✅ 통과 / ❌ 실패
- ESLint: ✅ 통과 / ❌ 실패
- 테스트: ✅ 통과 / ❌ 실패
- 빌드: ✅ 통과 / ❌ 실패

## 보안 감사 (pnpm audit)
- Security Audit: ✅ 통과 / ❌ 실패

## 📊 최종 판정
✅ 모든 항목 통과 — commit/push/PR 진행 가능합니다.
```

실패 항목이 있을 경우 핵심 에러 위치와 메시지를 요약하여 출력한다 (전체 로그 출력 금지).

### 4. 에러 발견 시 — 자동 수정 승인 요청

실패 항목이 **없으면** → 스킬 종료.

실패 항목이 **하나라도 있으면** 에러 내용을 먼저 보여준 뒤 아래 메시지를 출력하고 개발자의 응답을 기다린다:

```
❌ 위와 같이 실패 항목이 발견되었습니다. 지금 바로 자동 수정을 진행할까요?

자동 수정 가능 항목:
  - 포맷 오류 → pnpm format
  - ESLint 오류 → pnpm lint:fix

코드 직접 수정 필요 항목:
  - TypeScript 타입 오류 / 테스트 실패 / 빌드 오류 / 보안 취약점

👉 자동 수정을 진행하려면 "예" 또는 "수정"을 입력하세요.
   직접 수정하려면 "아니오"를 입력하세요.
```

- 개발자가 **"아니오"** → 스킬 종료.
- 개발자가 **"예" / "수정"** → 5단계로 진행.

### 5. 미커밋 파일 확인 및 처리 방법 선택

```bash
git status --short
```

미커밋 변경사항이 **없으면** → 바로 6단계(자동 수정)로 진행.

미커밋 변경사항이 **있으면** 아래 메시지를 출력하고 개발자의 선택을 기다린다:

```
⚠️  커밋되지 않은 변경사항이 있습니다:
{git status --short 결과}

에러 수정 전에 처리 방법을 선택해 주세요:

  A) 지금 변경사항을 먼저 commit한 뒤 에러를 수정합니다
     → 안전: 에러 수정 전 현재 상태를 보존할 수 있습니다

  B) commit 없이 바로 에러를 수정합니다
     ⚠️ 주의: 수정 중 문제가 생겨도 현재 상태로 되돌리기 어렵습니다

👉 A 또는 B를 입력하세요.
```

**A 선택 시:**

커밋 메시지를 개발자에게 요청한다:

```
커밋 메시지를 입력해 주세요 (예: "chore: pre-check 전 현재 상태 저장"):
```

입력 받은 후 staged 파일 기준으로 커밋한다:

```bash
git add -u
git commit -m "{입력받은 메시지}"
```

커밋 완료 확인 후 6단계로 진행.

**B 선택 시:**

```
⚠️  commit 없이 에러 수정을 진행합니다.
    문제 발생 시 `git diff`로 변경 내용을 확인하거나 `git stash`로 수동 복구하세요.
```

6단계로 진행.

### 6. 에러 자동 수정

실패 항목 유형별로 순서대로 수정을 시도한다:

#### 자동 수정 (명령어로 처리)

| 실패 항목                  | 수정 명령어                    |
| -------------------------- | ------------------------------ |
| 포맷 오류                  | `pnpm format`                  |
| ESLint 자동 수정 가능 오류 | `pnpm lint:fix`                |
| 포맷 + 린트 동시           | `pnpm format && pnpm lint:fix` |

#### 코드 직접 수정 (파일 편집)

| 실패 항목            | 처리 방법                                                       |
| -------------------- | --------------------------------------------------------------- |
| TypeScript 타입 오류 | 에러 위치·메시지 출력 → 해당 파일을 읽어 원인 파악 후 수정      |
| 테스트 실패          | 실패한 테스트와 원인 출력 → 관련 코드/테스트 파일 수정          |
| 빌드 오류            | 빌드 에러 메시지 분석 → 원인 파일 수정                          |
| 보안 취약점 (audit)  | 취약 패키지명·버전 출력 → `pnpm update {패키지}` 또는 대안 안내 |

파일 수정 시 반드시 파일을 먼저 읽은 뒤 편집한다 (환각 방지 규칙 준수).

### 7. 수정 후 재검증

수정 완료 후 동일한 두 명령어를 다시 실행하여 결과를 확인한다:

```bash
pnpm ci:check
pnpm audit --audit-level=high
```

결과를 아래 형식으로 출력한다:

```
## 🔄 수정 후 재검증 결과

## CI 검사 (pnpm ci:check)
- 포맷 검사: ✅ 통과 / ❌ 여전히 실패
- TypeScript 타입 체크: ✅ 통과 / ❌ 여전히 실패
- ESLint: ✅ 통과 / ❌ 여전히 실패
- 테스트: ✅ 통과 / ❌ 여전히 실패
- 빌드: ✅ 통과 / ❌ 여전히 실패

## 보안 감사 (pnpm audit)
- Security Audit: ✅ 통과 / ❌ 여전히 실패

✅ 모든 항목 수정 완료 — 이제 commit/push/PR 진행 가능합니다.

또는

❌ 일부 항목이 아직 실패합니다. 에러 내용을 확인하고 수동으로 추가 수정이 필요합니다.
```

재검증 실패 시 → 해당 항목의 에러 메시지를 다시 요약 출력하고 개발자에게 수동 수정을 안내한 뒤 종료.

## 주의

- 실패한 에러 로그는 전체 출력하지 않고 **핵심 에러 위치와 메시지만** 요약하여 출력한다.
- **개발자의 명시적 응답(승인) 없이 코드를 수정하거나 commit을 생성하지 않는다.**
- `git add -u`는 추적 중인 변경 파일만 스테이징하며, 새로 생성된 미추적 파일은 포함하지 않는다. 미추적 파일이 있으면 개발자에게 별도로 안내한다.
